# Original P11 viewer requirements and acceptance map

This read-only implementation audit is based on accepted recovery `57f812f0122aea43b085204777950010fd6c8c87`. It maps every clause of P11's original `scope_and_completion` in [tasks.json](tasks.json); it does not replace that contract or change its status. The selected implemented consumer is the computed material replay. Other repository and preserved standalone viewers are acknowledged separately, not silently credited as integrated features. No browser, performance, headset or numerical simulation was run for this audit.

**Status meanings:** implemented means inspectable code exists for the stated bounded contract; partial means some elements exist but the original clause is not closed; missing means no implementation was found in the inspected computed-material path; needs physical QA means a named device/runtime observation is still required. These are feature dispositions, not blanket statements about every file in the repository. Proposed acceptance steps below are future review criteria, not new validated performance promises.

## Performance protocol to specify before claiming completion

The original requirement contains no numeric budget. This audit therefore does not invent a validated frame-rate target. Before implementation tuning, record the supported workstation/browser/DPR and target headset refresh rate; choose explicit pass/fail budgets for load time, peak memory, p95 frame time, input-to-visible latency, dropped-frame fraction and session duration.

Use at least the committed four-module example, a declared largest supported export, and malformed/oversized inputs. Include cold load, replay across all frames, repeated module selection, rotation/zoom during replay, resize and prolonged session/reload. Measure actual frame timing, memory and responsiveness; passing the 25 MB size check is not a performance result. Separate source-sample timing from display timing: decimation or reduced rendering rate must never imply modified scientific time or invented interpolated states. Document any supported-size cap with the measured configuration and visible failure behavior.

Hardware QA must additionally record render resolution/refresh settings, device/runtime/browser, tracking origin and units, controller/hand input, dropped frames and comfort/accessibility observations. Desktop functional success is a prerequisite, not a substitute.

## Existing adjacent capabilities and limits

Source inspection found [XRRobotBridge](../../src/xr_robot_bridge.py) and [robotics XR tests](../../tests/test_robotics_xr_product.py): bounded command acceptance, deadman requirements, explicit stop and digital-twin history exist. They remain separate from the science viewer. The legacy [WebXR haptic controller](../../src/webxr_haptic_controller.py) computes pose-derived numeric outputs; its unit tests do not exercise a physical controller. [WebGPUSpatialVisualizer](../../src/webgpu_spatial_visualizer.py) constructs a shader string and returns a compiled-status label without invoking a GPU compiler in that function; that label is not GPU execution or performance evidence. The historical HTML viewer supplies OrbitControls but is not the material schema consumer.

The previously preserved standalone workbench carries its own generic scenes, abstract 13D projection and tetrahedral reconstruction. Its historical 138-test log and source associations are useful provenance; they do not automatically close any integration, image or device row above. This matrix deliberately distinguishes source existence, integrated behavior and hardware evidence.

## Continuation order

First connect immutable run/source/input and per-object witness identities to the existing desktop consumer, preserving original metre coordinates and separate ledgers. Then add coverage/failure/uncertainty inspection and synchronized plots/navigation under that contract. Establish a measured desktop performance baseline before enlarging datasets or claiming headset readiness. Physical attachment/image constraints and hardware QA remain separate evidence gates. Participant feedback, collaboration and interchange should follow explicit identity/state contracts rather than introduce an unrelated viewer rewrite.

The historical adapter document and its `current_repository_visualizers_are_direct_consumers=False` compatibility field describe the pre-consumer checkpoint. The later material replay is a direct consumer; [material_viewer_replay.md](../material_viewer_replay.md) explicitly explains why that historical flag remains unchanged. Do not mistake it for evidence that accepted replay is missing.
