# Computed material replay

Open `docs/docs/material-viewer.html` through a local HTTP server, then choose
**Load computed example**, or load a JSON export from the existing
`export_fold_material_viewer_frames` adapter. The historical visualizer links
to this companion page. No remote rendering dependencies are required.

The example is generated by `python -m scripts.export_material_viewer_example`
from the unchanged powered constitutive material simulation through 0.4 s.
Its source report is committed in `docs/experiments/material-viewer-source.json`;
the export records its normalized-text SHA-256. The browser displays that
reported hash without claiming independent verification of an uploaded source.

The desktop renderer rotates the actual three-dimensional metre vertices,
using an orthographic projection and depth-sorted faces. Each module stays in
its own local frame. A fixed camera scale across all modules preserves their
relative sizes. Replay selects original frames using their physical timestamps;
it does not interpolate geometry or invent dynamics. Panels are midsurfaces,
bridges lines and hubs points, not finite-thickness solids or physical joints.

Reserve, delivered work, external input and the three loss owners are shown
separately in joules. Network edge potentials and endpoint work are explicitly
network-wide. Delivered work is transfer, not additional storage. The existing
export does not contain mechanical-energy totals, so this viewer cannot
display a complete energy balance. The adapter's historical compatibility flag
is left unchanged to preserve its source checkpoint; this page is now a direct
consumer of that contract.

P11 remains open: full image correspondence, physical assembly placement,
headset/WebXR integration and physical headset validation are not established
by this desktop replay. No 69-component flow correspondence is inferred.

Validation: `node --test --test-concurrency=1 tests/test_material_viewer.mjs`
checks the computed example, invalid inputs, physical-time replay and 3D
projection. Visible browser checks are recorded separately in the PR.
